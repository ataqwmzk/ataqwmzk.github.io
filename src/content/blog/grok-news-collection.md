この記事は2本立ての後編です。前編で調べたことを使って、ニュースを全自動で集める仕組みを作りました。

- 前編：[YouTuberは海外の最新ニュースをどう集めている？ AIでどこまでできるか試した](https://lzuna0032-design.github.io/izuna.github.io/blog/youtuber-news-research/)
- 後編（この記事）：その結果をもとにした自動化の仕組み

## 結論：できあがった仕組み

```
Grok（毎時・終日で自動実行）
　↓  Xの投稿とWebを見てニュースを集める
Gmail にメールで届く
　↓  朝4:30・夕16:30（Claudeの定期タスク）
Claude が読んで、まとめて、出典を確かめる
```

いきなりこの形になったわけではありません。指示文は5回以上作り直しました。以下で、**前編のどの結果から、なぜこうしたのか**と、**どう変わってきたか**を書きます。

## 前編の結果 → こう決めた

| 前編で分かったこと | だからこうした |
|---|---|
| 速さの正体は「見張り続けること」 | 頼まれたときに調べるのではなく、毎時自動で実行する |
| Xの速報はGrokがいちばん強かった | 集める係はGrokにする |
| 確かめるのはClaudeが向いていた。ただし見落としもある | まとめて確かめる係はClaudeにする |
| AIにAIを採点させると甘くなる | Claudeには「正しいか判断して」ではなく、出典を実際に開いて確かめさせる |
| 他のAIが古い話を「最新」に混ぜた | 「何時間以内のニュースだけ」と時間で区切る |
| 出典がトップページだった | 個別の記事URLだけにする |
| 数字がずれていた | 数字は出典のまま書かせる |
| Xの速報アカウントは話を盛っていた | 情報の確かさにラベルを付ける |

## 指示文の中身（最終版のルール）

| ルール | ねらい |
|---|---|
| 10分野×最大2件 | 国際・政治、経済、テック・AI、科学、スポーツ、音楽、フェス、エンタメ、災害、その他。全部を広く見る |
| 選ぶ順番は「公式発表あり」→「複数の報道」→「新しさ」 | 「重要そうなもの」にすると、選ぶ段階でAIの好みが入る |
| 事実だけ。意見・予想・形容詞は書かない | 話を盛らせない |
| ラベル：[公式]／[報道]／[X速報] | どれくらい確かな情報かを分ける |
| ラベルと本文の強さをそろえる | [報道]なのに「公式に発表」と書かせない |
| 発言は原文のまま引用する | 言い換えで意味が変わるのを防ぐ |
| Xは「手がかり」に使い、裏が取れたら報道・公式を出典にする | Xの速さを活かしつつ、盛った投稿は載せない |
| 1行目に「収集時刻」 | Claudeが時間帯ごとに整理できる |
| 全体2,500字以内 | メールが途中で切れないようにする |

## 作り直しの経緯

### 1回目：テックだけ・24時間以内

最初は、前編の実験と同じ「海外テック・AI」だけでした。24時間以内のニュースを最大5件です。前編で見えた失敗（古い話、トップページの出典、数字のずれ、盛られたX投稿）への対策を、最初から入れました。

### 2回目：全世界・全分野へ

スポーツ、音楽、フェスなど、全部の分野を見たくなりました。そのまま広げると件数が際限なく増えるので、「10分野×最大3件」と枠を決めました。どこの国の話か分かるように「国・地域」の欄も足しました。

### 3回目：届いたメールを見て直した

実際にGmailに届いた2通を、Claudeに読ませて確かめました。問題が4つありました。

| 届いたメールの問題 | 直したこと |
|---|---|
| 出典に一覧ページ（Reutersの /world/）が入っていた | 一覧ページを具体例つきで禁止。URLを開いて確かめたものだけにする |
| [報道]ラベルなのに、本文は「公式に発表した」と断定していた | 「公式に発表」と書けるのは[公式]のときだけにする |
| 同じ発言の訳が、1通目と2通目で違っていた | 発言は原文をそのまま引用する |
| メールが途中で切れて、1分野しか読めなかった | 1分野2件、全体2,500字以内に減らす |

前編で心配していた失敗が、実際のメールでも起きていました。対策を入れていても、AIは守りきれないことがあります。だから、後でClaudeが確かめる工程を入れる必要がありました。

### 4回目：Xの使い方を決めた

Grokの強みはXなので、Xをちゃんと見させるルールを足しました。前編で、記者本人の投稿は速くて正確、まとめアカウントは盛っていた、と分かったことがもとになっています。

- Xで見つけた話は、まず報道や公式で裏を取る
- 裏が取れないときは、記者・当事者・公式アカウントの投稿だけ[X速報]で載せる
- 出典は投稿そのもののURLにする
- 「いいね」の多さで選ばない

### 5回目：実行の間隔を決めた

ここがいちばん迷いました。

| 案 | どうなったか |
|---|---|
| 毎時・24時間以内 | 毎回ほぼ同じニュースになる → ✕ |
| 8時間おき・8時間以内 | 重なりは減る。でも速さが落ちる |
| **毎時・1時間以内** | 速さ優先でこれに決定。何もない分野は省略して、メールを短くする |

ポイントは、**実行の間隔と「何時間以内」をそろえる**ことです。そろっていないと、前の回と同じニュースが何度も届きます。

### 6回目：Claudeのまとめ係を作った

毎時24通のメールは、全部は読めません。そこで、Claudeの定期タスクで1日2回まとめることにしました。

```
4:30の回 → 前日16:00〜当日4:00のメール
16:30の回 → 当日4:00〜16:00のメール
```

まとめ係のClaudeには、次のことをさせています。

- 同じ出来事が何通にも出てきたら、1つにまとめる
- [X速報]、断定が強いもの、数字や発言があるものは、出典を開いて確かめる
- 食い違いがあれば、直さずに「Grokの記載／確認結果」と両方書く
- メールがなければ、自分でニュースを探して埋めない

最後の1行は、前編の反省からです。AIは「何かを出さなきゃ」と、確かでないものまで出してしまうことがあるからです。

実行時刻は、最初は3:05と16:05にしました。そのあと4:30と16:30に変えて、まとめる時間帯もそれに合わせました。

### 7回目：遅れで、すき間があくと分かった

動かしてみると、Grokの実行は予定より10分ほど遅れることがありました。収集時刻が12:09のときもありました。

```
12:09 に収集 → 11:09〜12:09 を調べる
13:15 に収集 → 12:15〜13:15 を調べる
　　　　　　　　↑ 12:09〜12:15 の6分が抜ける
```

遅れは毎回ちがうので、指示文では直せません。そこで、調べる範囲を **「過去90分以内」** に広げることにしました。30分までの遅れなら、すき間があきません。

そのかわり、前後のメールで同じニュースが出ることがあります。でも、これはClaudeのまとめで1つにまとめるので、問題になりません。**集める側は少し多めに拾って、まとめる側で重複を消す**、という分担です。

## まとめ：作ってみて分かったこと

| 分かったこと | 理由 |
|---|---|
| ルールを書いても、AIは守りきれない | 届いたメールで、禁止した失敗が起きていた |
| だから「集める係」と「確かめる係」を分ける | 前編の実験と同じ結論になった |
| 時間の区切りは、実行の間隔とそろえる | ずれると重複か取りこぼしが出る |
| 遅れは前提にして、少し重ねて集める | 重複は後で消せるが、抜けた分は戻らない |

## まだ分からないこと

- 新しい指示文で、メールが途中で切れずに届くか
- 「過去90分」にして、取りこぼしが実際に減るか
- Claudeの定期タスクが、毎回ちゃんとGmailを読めるか（まだ最初の実行前です）

この記事は2026年11月10日時点の内容です。GrokやClaudeの機能は変わることがあるので、使う前に最新の画面で確かめてください。
